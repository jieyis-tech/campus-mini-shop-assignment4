# Reflection

The most interesting software-engineering lesson from this exercise was that an AI loop became much more reliable when each iteration inherited a reviewed specification, a concrete checklist, and executable tests instead of only a broad request to build a shopping site. Separating specification, review, planning, and implementation made errors observable at the boundary between stages: the requirements reviewer removed ambiguous validation behavior, the planning loop mapped it to tests, and the build tests then caught a real Flask application-context defect that a plausible-looking implementation had missed. Version-control checkpoints also made the process easier to supervise because the base system remained a working reference before the extension changed the database and user flow. The experience showed me that AI can generate code quickly, but ordinary software-engineering controls—small scope, independent review, deterministic validation, automated tests, and recoverable commits—are what make the result trustworthy.
